# Финальный аудит Career Quest

Дата: 23 сентября 2026 года.

## Вердикт

**Проект готов к локальной демонстрации жюри на проверенном Windows-окружении.** Обязательный сценарий Career Quest реализован; запуск из чистой копии, импорт, прогресс, приватность, сохранение данных и реальный OpenAI прошли проверку. Блокирующих дефектов в выполненном прогоне не обнаружено.

Это вердикт о хакатонном MVP. Производственная эксплуатация, нагрузка, другие ОС и неизвестные контрольные данные жюри этим аудитом не подтверждаются. Оценку жюри в баллах отчёт не прогнозирует.

## Основания и объём

- Повторно прочитан исходный DOCX «HackAlem AI_ Career Quest - платформа геймификации жизненного цикла сотрудника..docx», включая must-have, ограничения и критерии оценки.
- Сопоставлены 11 требований пользователя к README и фактический README.
- Проверены backend, расчёт навыков, допуск и выбор рекомендаций, импорт, авторизация, ограничения запросов, кошелёк, клиентские сценарии, скрипты запуска и тесты.
- Выполнены тесты в рабочем окружении и повторно в чистом виртуальном окружении.
- Для запуска скопированы отслеживаемые файлы проекта в отдельный временный каталог. Рабочая база пользователя не изменялась.
- Через браузер проверены вход сотрудника, язык из профиля, переключение RU/EN, отображение сохранённых навыков и награды, выход и HR-вход. Импорт и изменения дополнительно проверены HTTP-запросами к отдельному серверу.

## 3. Воспроизведение запуска жюри

1. Подготовлена отдельная копия отслеживаемых файлов без готовой базы и виртуального окружения.
2. Запущено `powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Port 8773`.
3. Создан новый `.venv`, зависимости установлены; `pip check` сообщил `No broken requirements found`.
4. Через скрытые приглашения заданы отдельные временные пароли employee/hr. Вход обоих аккаунтов проверен.
5. Загружены `tests/fixtures/employees.json` и `tests/fixtures/activity_history.csv`: 3 профиля, 4 записи.
6. Проверены рекомендации всех трёх профилей и минимум три основания для каждого шага в резервном режиме.
7. Для E0001 выполнен EV_005: два навыка выросли, XP 300→400. Обмен кино уменьшил баланс до 100 и создал один DEMO-NOT-VALID-код.
8. Командой из README создан demo-critical для импортированного CONTROL_CRITICAL.
9. Сервер остановлен и запущен через `.\.venv\Scripts\python.exe scripts\start.py --port 8773`. Повторное создание аккаунтов не потребовалось; вход, импортированные данные, навыки, баланс и код сохранились.

Для защиты на стандартном порту достаточно `.\run.ps1` и адреса http://127.0.0.1:8000/. Python и интернет для установки зависимостей — предварительные условия. Для демонстрации именно AI нужен действующий ключ; без него интерфейс честно показывает резервный подбор.

Проверка выполнена через `scripts/check_openai.py --prompt-key` в отдельной копии, модель `gpt-4o-mini`. Временный ключ введён скрыто, не записан в файлы проекта; процесс проверки завершён.

## 5. Некритичные замечания и границы

1. **Адрес после создания аккаунта.** `scripts/create_account.py` печатает `http://127.0.0.1:8000/` независимо от выбранного порта сервера. При проверке на 8773 пришлось использовать фактический адрес. Стандартному запуску по README это не мешает.
2. **Зависимости фиксированы частично.** Прямые версии закреплены, транзитивные — нет. Чистая установка сейчас проходит, но её состав может измениться. Для сохранения идентичного окружения полезен отдельный lock/constraints-файл.
3. **Выполнение — симуляция MVP.** Будущая сессия делает событие доступным для рекомендации, а кнопка записывает завершение на дату среза. Это демонстрация пересчёта, не подтверждение фактического посещения. Реальные награды требуют проверки результата.
4. **Повторный показ меняет данные.** Импорт требует новых идентификаторов; завершения и обмены сохраняются. Для чистой репетиции следует использовать отдельную копию или отдельный путь CAREER_QUEST_DB, а не удалять рабочую базу.
5. **Ограниченный охват.** Нет нагрузочного теста, полной матрицы браузеров/ОС, проверки всех возможных данных жюри, аудита всей Git-истории или полноценного пентеста. Успешные тесты не доказывают отсутствие любых дефектов.
