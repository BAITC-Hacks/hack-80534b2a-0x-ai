# Безопасность Career Quest

## Локальный запуск

Стандартная команда запускает сервер на `127.0.0.1:8000`. Доступ к данным определяется серверной сессией и аккаунтом из SQLite. Аккаунт сотрудника видит собственный профиль; HR получает агрегаты, импорт и настройку OpenAI. Пароли сохраняются как salted scrypt хеши, токены сессий — как SHA-256 хеши. Для изменений проверяются CSRF-токен и Origin.

Ключ, введённый в HR-интерфейсе, хранится в окружении процесса сервера. Он не возвращается API и не сохраняется в SQLite. Перезапуск теряет введённое значение; ключ, заданный родительским окружением, снова наследуется при новом запуске. Отключение ключа не отменяет уже отправленные провайдеру запросы.

## Переменные окружения

`.env.example` — справочный образец, **не автоматически загружаемая конфигурация**. Создание `.env` из этого файла само по себе не меняет настройки приложения. Поддержаны `OPENAI_API_KEY`, `OPENAI_MODEL`, `CAREER_QUEST_DB` и `DEMO_EMPLOYEE_ID`. Последняя используется только при первоначальном создании аккаунтов.

Ключ можно ввести через сайт после входа как HR. Несекретные настройки перед запуском задаются в PowerShell, например:

```powershell
$env:OPENAI_MODEL = 'gpt-4o-mini'
$env:DEMO_EMPLOYEE_ID = 'E0001'
.\.venv\Scripts\python.exe scripts\start.py
```

Пароли не задаются через `.env.example`. Файлы `.env`, `.env.*`, SQLite и стандартные sidecar/резервные файлы исключены из Git; `.env.example` разрешён. Произвольные имена резервных копий, дампы и уже отслеживаемые файлы требуют отдельной проверки: `.gitignore` не удаляет их из индекса или истории.

## Ограничение запросов

`RequestBodyLimitMiddleware` должен быть подключён к приложению до разбора тела FastAPI. Он допускает до 64 КиБ в обычном запросе и до 10 100 000 байт для `/api/import` (два файла по 5 000 000 байт плюс multipart-заголовки). Лимит действует также без Content-Length и при потоковой передаче. Превышение возвращает HTTP 413 до запуска обработчика и multipart-парсера. Лимит каждого отдельного файла дополнительно проверяется импортом.

Буферизация ограничена размером одного разрешённого тела, но множество параллельных запросов и медленная передача по-прежнему требуют лимитов соединений и таймаутов на сервере или reverse proxy.

## GitHub и данные хакатона

ТЗ запрещает выносить предоставленный синтетический датасет за пределы хакатона. Каталог `data/` уже отслеживается Git и присутствует в истории. Прежде чем публиковать репозиторий открыто, нужно получить разрешение организаторов либо подготовить разрешённую версию данных и историю без запрещённых материалов. Закрытый репозиторий допускает только согласованный круг участников; приватность репозитория сама по себе не даёт разрешения на передачу данных.

Проверяйте staged diff и историю на ключи, пароли, базы, экспорты и ограничения данных перед публикацией. Проверка известных шаблонов секретов не гарантирует отсутствие любого секрета. Если секрет уже попал в удалённый репозиторий, его следует отозвать у провайдера: удаления файла недостаточно.

## Размещение в сети

Перед сетевым размещением нужны HTTPS, проверенная настройка доверенных proxy и Secure cookie, ограничения соединений/размеров/частоты запросов, бюджет провайдера и управление доступом к файлу SQLite. HTTP допустим для текущего loopback-сценария; не вводите API-ключ через незашифрованный сетевой адрес.

Текущее приложение рассчитано на один серверный процесс: данные в памяти и ключ, введённый через сайт, не синхронизируются между несколькими workers. Расширение до нескольких процессов требует общей согласованной модели состояния и ограничителей. Реальные персональные данные не входят в этот MVP.
