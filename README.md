# Career Quest

Career Quest — демонстрационный AI-навигатор развития сотрудника. Приложение использует синтетический набор Career Quest, подбирает добровольные развивающие активности с учётом профиля, требований грейда и истории участия и показывает HR агрегированные дефициты навыков.

## Запуск

Требуется Python 3.10 или новее и доступ к PyPI при первом запуске. В PowerShell из папки проекта выполните:

```powershell
.\run.ps1
```

Скрипт создаёт `.venv`, устанавливает зависимости и запускает сервер. Откройте <http://127.0.0.1:8000>. Остановка — `Ctrl+C`.

Без API-ключа работает многокритериальный резервный подбор. Чтобы включить AI-выбор, задайте ключ в текущем окне PowerShell перед запуском:

```powershell
$env:OPENAI_API_KEY = "ваш ключ"
# при необходимости:
$env:OPENAI_MODEL = "gpt-4o-mini"
.\run.ps1
```

Рекомендация использует OpenAI Chat Completions со строгой JSON Schema и сетевым таймаутом 8 секунд. Общий срок ожидания AI в отдельном endpoint — 8,5 секунды, затем возвращается резервный подбор. Профиль загружается независимо от рекомендаций. Модель выбирает только из прошедших проверку кандидатов. Текст причин собирается приложением из подтверждённых фактов. При отсутствии ключа, сетевой ошибке или некорректном ответе применяется локальный алгоритм.

## Демо

Приложение открывается в режиме сотрудника `E0001`. Кнопка в верхней панели переключает режим сотрудника и HR. В демо переключение роли не является корпоративной аутентификацией. Набор полностью синтетический; для реальных данных потребуется подключить корпоративный вход и закреплять роль и employee ID за проверенной сессией.

HR может загрузить `employees.json` с дополнительными профилями и/или `activity_history.csv`. Загрузка проверяет структуру, идентификаторы и связи до записи. Некорректный набор отклоняется целиком. После загрузки введите ID профиля в поле просмотра проверочного профиля в HR-обзоре, чтобы открыть его маршрут в демо-режиме сотрудника. Успешно загруженные данные сохраняются в локальной SQLite базе `career_quest.sqlite3`; файл находится в `.gitignore`.

Для демонстрации загруженного профиля укажите его ID через переменную `DEMO_EMPLOYEE_ID` и перезапустите приложение. По умолчанию используется `E0001`:

```powershell
$env:DEMO_EMPLOYEE_ID = "E0123"
.\run.ps1
```

Каталог `data/` содержит официальный синтетический стартовый набор и русскоязычный README к нему. Дата среза для дат событий и стажа берётся из `meta.as_of_date` (`2026-10-01`), а не из часов компьютера.

## Правила расчёта

- Целевой грейд — следующий в последовательности Junior → Middle → Senior → Lead; для Lead отображается текущий уровень.
- Начальный уровень навыка берётся из профиля. К нему хронологически добавляется `gain` завершённых строго после `last_review_date` мероприятий и не позже даты среза с ограничением `max_level`. Если навык уже выше потолка активности, он не снижается. Новое выполнение сохраняется датой среза. Выполнение в день оценки не увеличивает навыки: по правилам учитываются только более поздние даты.
- Рекомендации не включают обязательные мероприятия, события с невыполненными предпосылками или мероприятия, не подходящие роли и грейду. После завершения событие повторно исключается, кроме регулярного клуба `EV_036`.
- Резервный подбор учитывает закрытие разрывов следующего грейда (критичные навыки имеют больший вес), карьерную цель и историю участия. Отказы и пропуски влияют на ранжирование похожих событий, но не делают их недоступными автоматически.
- HR видит агрегаты дефицитов и список сотрудников как повод для личного диалога при двух и более событиях `no_show`, `declined` или `dropped` за последние шесть месяцев от даты среза. Это не рейтинг.

## API

- `GET /api/health` — состояние сервиса и дата среза.
- `GET /api/profile/{employee_id}?lang=ru|kk|en` — профиль сотрудника; требует заголовки `X-Demo-Role: employee` и `X-Employee-Id` с совпадающим ID.
- `GET /api/recommendations/{employee_id}?lang=ru|kk|en` — отдельная загрузка рекомендаций с теми же проверками доступа.
- `POST /api/complete` — завершить доступную добровольную активность сотрудника.
- `POST /api/import` — multipart загрузка полей `employees_file` и/или `history_file`; только HR.
- `GET /api/hr` — агрегаты по навыкам и сотрудникам; только HR.

Демо-заголовки нужны только для показа разграничения ролей на синтетических данных, а не для production-защиты.

## Языки и проверка

При первом открытии профиля интерфейс выбирает `preferred_language`. Ручной выбор сохраняется отдельно для каждого сотрудника в текущем браузере. Названия навыков раскрываются по нажатию и показывают описание на выбранном языке.

Проверки выполняются на временной SQLite базе, не затрагивая рабочие данные:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В `tests/fixtures/` находятся три синтетических контрольных профиля и история в формате датасета. Это собственные примеры для приёмки, а не официальные профили жюри. Их можно загрузить через HR-экран:

- `CONTROL_CRITICAL`: минимальный навык — публичные выступления, три пропуска клуба; приоритет получает критичный System Design.
- `CONTROL_PREREQUISITES`: Junior с отсутствующими навыками; проверяются нулевые уровни и ограничения допуска.
- `CONTROL_REPEAT`: завершённый ранее `EV_036` остаётся доступным для повторной рекомендации.

Проверки также охватывают сохранение выполнения и импорта после перезапуска, атомарный отказ при ошибке, границы даты оценки и среза, потолок роста навыка, HR-дефициты, демо-разграничение ролей, проверку ответа модели и резервный подбор при задержке. Реальный вызов OpenAI требует ключа в окружении и проверяется отдельно.
