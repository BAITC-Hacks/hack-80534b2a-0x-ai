# Career Quest

Career Quest — демонстрационный AI-навигатор развития сотрудника. Приложение использует синтетический набор Career Quest, подбирает добровольные развивающие активности с учётом профиля, требований грейда и истории участия и показывает HR агрегированные дефициты навыков.

## Запуск

Требуется Python 3.10 или новее и доступ к PyPI при первом запуске. В PowerShell из папки проекта выполните:

```powershell
.\run.ps1
```

Скрипт создаёт `.venv`, устанавливает зависимости и запускает сервер. Откройте <http://127.0.0.1:8000>. Остановка — `Ctrl+C`.

Без API-ключа работает многокритериальный резервный подбор. Чтобы включить AI-выбор, задайте ключ в текущем окне PowerShell перед запуском:

```powershell
$env:OPENAI_API_KEY = "ваш ключ"
# при необходимости:
$env:OPENAI_MODEL = "gpt-4o-mini"
.\run.ps1
```

Рекомендация использует OpenAI Chat Completions со строгой JSON Schema и сетевым таймаутом 8 секунд. Общий срок ожидания AI в отдельном endpoint — 8,5 секунды, затем возвращается резервный подбор. Профиль загружается независимо от рекомендаций. Модель выбирает только из прошедших проверку кандидатов. Текст причин собирается приложением из подтверждённых фактов. При отсутствии ключа, сетевой ошибке или некорректном ответе применяется локальный алгоритм.

## Вход и запуск в Windows

Если окружение `.venv` уже установлено, выполните одну команду из папки проекта:

```powershell
.\.venv\Scripts\python.exe scripts\start.py
```

При первом запуске программа создаст два аккаунта: `employee` для сотрудника `E0001` и `hr` для HR. Задайте разные пароли длиной от 12 символов в скрытом приглашении. Для другого начального сотрудника до первого запуска задайте `DEMO_EMPLOYEE_ID`. После запуска войдите на сайте как HR и в блоке «Настройка AI-рекомендаций» введите API-ключ OpenAI. Без ключа действует резервный подбор. Значения ключа и паролей не записываются в логи или конфигурационные файлы.

Ключ, введённый в отдельную программу проверки, не передаётся серверу автоматически: для сервера его нужно ввести в HR-кабинете. Ключ применяется через защищённый endpoint только для HR, действует в окружении текущего процесса и не возвращается в ответах API. Поле очищается после отправки. Кнопка «Отключить OpenAI» удаляет ключ из окружения и включает резервный подбор. При завершении процесса ключ теряется. Аккаунты и хеши паролей сохраняются в SQLite.

Откройте <http://127.0.0.1:8000> и войдите выбранным аккаунтом. Свободного переключателя ролей нет. Сотрудник видит только свой профиль. HR видит агрегаты, может импортировать данные и открывать профили сотрудников для просмотра; отмечать их активности выполненными HR не может.

Дополнительный аккаунт для уже существующего или загруженного профиля создаётся локальной командой администратора:

```powershell
.\.venv\Scripts\python.exe scripts\create_account.py --username reviewer --role employee --employee-id CONTROL_CRITICAL
```

Пароль вводится скрыто. Публичной регистрации и стандартных паролей нет. Повторное создание логина не перезаписывает пароль.

Сессия хранится на сервере, срок жизни — 8 часов. Браузеру выдаётся случайный идентификатор в `HttpOnly`, `SameSite=Strict` cookie (на HTTPS также `Secure`). Для запросов изменения данных проверяются CSRF-токен и Origin. Выход отзывает серверную сессию. Клиентские заголовки `X-Demo-Role` и `X-Employee-Id` не дают прав доступа. Есть ограничение частоты попыток входа и запрет кеширования API-ответов. Корпоративный SSO остаётся за пределами MVP.

HR загружает дополнительные `employees.json` и/или `activity_history.csv`. Некорректный набор отклоняется целиком. Загруженные данные сохраняются в `career_quest.sqlite3`, который исключён из Git. Каталог `data/` содержит синтетический стартовый набор; дата среза — `2026-10-01`.

## Правила расчёта

- Целевой грейд — следующий в последовательности Junior → Middle → Senior → Lead; для Lead отображаются требования и подбираются активности для развития в текущем грейде.
- Начальный уровень навыка берётся из профиля. К нему хронологически добавляется `gain` завершённых строго после `last_review_date` мероприятий и не позже даты среза с ограничением `max_level`. Если навык уже выше потолка активности, он не снижается. Новое выполнение сохраняется датой среза. Если оценка уже сделана в дату среза, кнопка выполнения блокируется с объяснением, а API возвращает 409 без записи: учитываются только более поздние даты. Самостоятельно изменять дату ради начисления нельзя.
- Рекомендации не включают обязательные мероприятия, события с невыполненными предпосылками или мероприятия, не подходящие роли и грейду. После завершения событие повторно исключается, кроме регулярного клуба `EV_036`.
- Резервный подбор учитывает закрытие разрывов следующего грейда (критичные навыки имеют больший вес), эффективный прирост до требований карьерной цели и историю участия. Цель учитывается отдельно для каждого мероприятия, включая смену роли; ограничения допуска по текущей роли сохраняются. Похожими считаются события с общими навыками и совпадающим типом либо форматом. Отказы и пропуски влияют на ранжирование, но не запрещают добровольное участие.
- Импорт проверяет объединённую историю: после завершения добровольное мероприятие не повторяется, кроме `EV_036`. Ежегодные обязательные комплаенс-курсы стартового набора могут повторяться и не участвуют в рекомендациях. Проверяются даты найма, сочетания статусов и форматов, назначение для `declined`, дедлайн для `overdue`, допустимость `score`. Любая ошибка отклоняет всю загрузку.
- HR видит агрегаты дефицитов и список сотрудников как повод для личного диалога при двух и более событиях `no_show`, `declined` или `dropped` за последние шесть месяцев от даты среза. Это не рейтинг.

## API

Все бизнес-endpoint требуют серверной сессии. POST-запросам также нужен заголовок `X-CSRF-Token`, возвращаемый при входе или чтении текущей сессии.

- `POST /api/auth/login` — JSON `{username, password}`, выдаёт cookie сессии и CSRF-токен.
- `GET /api/auth/session` — текущий пользователь и роль.
- `POST /api/auth/logout` — отзыв сессии.
- `GET /api/profile/{employee_id}` — собственный профиль либо просмотр сотрудника для HR.
- `GET /api/recommendations/{employee_id}?lang=ru|kk|en` — рекомендации, проверенные основания и числовые данные в `evidence`.
- `POST /api/complete` — выполнение активности только владельцем профиля; возвращает прогресс и список изменений `changes`.
- `POST /api/import` — multipart `employees_file` и/или `history_file`; только HR.
- `GET /api/hr` — агрегаты и список сотрудников для диалога; только HR.
- `GET/POST/DELETE /api/settings/openai` — состояние, установка и удаление ключа; только HR, изменения требуют CSRF. Состояние сообщает только наличие ключа и модель, не подтверждает доступ к провайдеру.
- `GET /api/health` — открытая проверка работоспособности.

## Языки и проверка

### Проверка настоящего OpenAI

Если PowerShell запрещает запуск `.ps1`, используйте Python напрямую:

```powershell
.\.venv\Scripts\python.exe scripts\check_openai.py --prompt-key
```

Вставьте API-ключ в скрытое приглашение и нажмите Enter. Изменение политики Windows не требуется. В этом варианте ключ находится только в окружении процесса проверки и не передаётся уже работающему серверу. Результат сохраняется в `openai-verification.json`.

В PowerShell из папки проекта запустите `./check-openai.ps1`. Если ключ ещё не задан, скрипт запросит его со скрытым вводом и сохранит только в переменной окружения текущего терминала. После успешной проверки запускайте `./run.ps1` в том же терминале. Уже работающий сервер нужно предварительно остановить.

Скрипт отправляет три синтетических контрольных профиля (без имён и идентификаторов сотрудников) в OpenAI. Проверяет фактический ответ модели, допустимость выбранных мероприятий, несколько оснований, приоритет критичного навыка, повторный клуб и время ответа. Резервный алгоритм не используется. Отчёт `openai-verification.json` содержит итог, модель, длительность и идентификаторы мероприятий; ключ и полные ответы провайдера не сохраняются. `PASS` означает успешное прохождение данного прогона; это не заменяет проверку на официальных профилях жюри.

Используется строгий JSON Schema согласно [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Ошибки доступа, соединения, отказ модели и неподтверждённые основания не засчитываются как успешный AI-подбор.

При первом открытии профиля интерфейс выбирает `preferred_language`. Ручной выбор сохраняется отдельно для каждого сотрудника в текущем браузере. Названия навыков раскрываются по нажатию и показывают описание на выбранном языке.

Проверки выполняются на временной SQLite базе, не затрагивая рабочие данные:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

В `tests/fixtures/` находятся три синтетических контрольных профиля и история в формате датасета. Это собственные примеры для приёмки, а не официальные профили жюри. Их можно загрузить через HR-экран:

- `CONTROL_CRITICAL`: минимальный навык — публичные выступления, три пропуска клуба; приоритет получает критичный System Design.
- `CONTROL_PREREQUISITES`: Junior с отсутствующими навыками; проверяются нулевые уровни и ограничения допуска.
- `CONTROL_REPEAT`: завершённый ранее `EV_036` остаётся доступным для повторной рекомендации.

Проверки также охватывают сохранение выполнения и импорта после перезапуска, атомарный отказ при ошибке, границы даты оценки и среза, потолок роста навыка, HR-дефициты, разграничение ролей, проверку ответа модели и резервный подбор при задержке. Реальный вызов OpenAI требует ключа в окружении и проверяется отдельно.

Проверки `tests/test_sessions.py` выполняют реальные HTTP-запросы к отдельному серверу с временной базой: подмена роли, чужой профиль, HR-просмотр без права выполнения, CSRF, истечение сессии, повторное использование cookie после выхода, отсутствие открытых паролей и токенов в базе.

## Демонстрация и настройки

Сценарий защиты: [DEMO.md](DEMO.md). После импорта интерфейс показывает ID затронутых сотрудников с кнопками безопасного HR-просмотра. Карточки рекомендаций показывают расчёт навыков и ближайшую доступную сессию; предпросмотр не записывает выполнение и не обещает кадрового повышения.

[.env.example](.env.example) — справочник поддерживаемых переменных. Приложение **не загружает `.env` автоматически**: задавайте переменные окружения перед запуском либо вводите ключ в HR-кабинете. Реальные ключи и пароли в образец не добавляются.

Защита и ограничения публикации описаны в [SECURITY.md](SECURITY.md). Тело запроса ограничено до разбора multipart: 64 КиБ обычно и 10 100 000 байт для импорта; каждый файл — максимум 5 000 000 байт. Рекомендации кешируются на 60 секунд (резервные — на 10); изменение данных или ключа сбрасывает кэш. Одновременные одинаковые запросы используют один расчёт. Допускается до 6 новых расчётов на аккаунт и до 60 на процесс за минуту, максимум 2 параллельных расчёта. При превышении частоты — HTTP 429 с `Retry-After`, при занятых вычислителях или таймауте — резервный подбор. Ограничения и состояние рассчитаны на один серверный процесс.

Сохранённый `openai-verification.json` относится к предыдущему прогону. После изменения персонализации новый реальный прогон выполняется отдельно указанной выше командой и требует ключа; локальные тесты платный API не вызывают.
